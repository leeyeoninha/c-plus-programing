01

이론 확인 문제 — 4지선다 16문항

보기를 누르면 바로 정답 여부가 표시됩니다. 점수는 매기지 않습니다 — 틀린 문항의 해설을 읽고 넘어가세요.

Q1. 다음 중 추상 클래스(abstract class)에 대한 설명으로 옳은 것은?

①객체를 만들 수 있지만 가상 함수는 하나도 가질 수 없다.
②객체를 만들 목적이 없는 클래스이며, 보통 기반 클래스로 사용한다.
③모든 멤버 함수가 순수 가상 함수여야만 추상 클래스가 된다.
④파생 클래스를 만들 수 없도록 봉인된 클래스다.

정답 및 해설 보기

정답 ②

추상 클래스는 그 자체로는 너무 일반적이어서 객체를 만들지 않을 목적으로 쓰고, 파생 클래스가 빠진 부분을 채우게 합니다. 순수 가상 함수를 하나 이상 가지면 추상 클래스가 되므로 ③은 틀렸고, 파생 클래스는 얼마든지 만들 수 있으므로 ④도 틀렸습니다.

Q2. 다음 중 순수 가상 함수의 선언으로 옳은 것은?

①virtual void draw() const = 0 { }
②virtual void draw() const = nullptr;
③virtual void draw() const = 0;
④pure virtual void draw() const;

정답 및 해설 보기

정답 ③

선언 끝에 = 0을 붙이며, 이 0을 순수 지정자(pure specifier)라고 합니다. ①처럼 본문을 함께 두면 순수 지정자를 쓸 수 없고, ②는 문법이 아니며, ④의 pure virtual은 C++에 없는 표기입니다.

Q3. 추상 클래스의 객체를 만들 수 없는 이유로 가장 알맞은 것은?

①생성자가 자동으로 만들어지지 않기 때문
②크기가 0으로 계산되기 때문
③소멸자를 가질 수 없기 때문
④순수 가상 함수의 구현이 없어, 호출할 대상이 없는 불완전한 객체가 되기 때문

정답 및 해설 보기

정답 ④

순수 가상 함수는 구현을 제공하지 않습니다. 그런 함수를 가진 객체를 만들면 호출할 본문이 없으므로, 언어가 객체 생성 자체를 막습니다. 생성자·소멸자는 추상 클래스에도 정상적으로 존재합니다.

Q4. 가상 함수와 순수 가상 함수의 차이를 가장 정확하게 설명한 것은?

①가상 함수는 구현을 가지며 재정의가 선택이지만, 순수 가상 함수는 구현이 없고 구체 파생 클래스가 반드시 재정의해야 한다.
②가상 함수는 재정의할 수 없고, 순수 가상 함수만 재정의할 수 있다.
③둘 다 구현이 없으며, 차이는 접근 지정자뿐이다.
④가상 함수는 실행 시간에, 순수 가상 함수는 컴파일 시간에 호출된다.

정답 및 해설 보기

정답 ①

차이는 구현의 유무와 재정의의 강제성입니다. 순수 가상을 재정의하지 않은 파생 클래스는 그대로 추상 클래스로 남습니다.

Q5. 기반 클래스의 순수 가상 함수 earnings()를 재정의하지 않은 파생 클래스에 대한 설명으로 옳은 것은?

①기반의 earnings()가 자동으로 호출된다.
②컴파일은 되지만 실행하면 예외가 발생한다.
③그 파생 클래스도 추상 클래스가 되어 객체를 만들 수 없다.
④0을 반환하는 기본 구현이 자동으로 만들어진다.

정답 및 해설 보기

정답 ③

순수 가상은 구현이 없으므로 자동으로 무언가가 호출될 수 없습니다. 재정의가 없는 파생 클래스 역시 추상 클래스가 되고, 그 객체를 만들려는 순간 컴파일 오류가 납니다(진단 1).

Q6. 추상 기반 클래스 Employee에 대해 할 수 있는 것은?

①Employee e("Kim");처럼 객체를 직접 만든다.
②Employee* p = new SalariedEmployee("Kim", 3000);처럼 파생 객체를 가리키게 한다.
③new Employee("Kim")으로 동적 할당한다.
④Employee를 값으로 배열에 담는다.

정답 및 해설 보기

정답 ②

추상 클래스의 객체는 만들 수 없지만(①③④), 그 클래스의 포인터와 참조는 선언할 수 있고 파생 객체를 가리켜 다형적으로 다룰 수 있습니다.

Q7. 교재 12.6의 Employee에서 earnings()를 순수 가상으로 선언한 이유로 가장 알맞은 것은?

①모든 직원의 급여가 항상 0이기 때문
②파생 클래스가 급여를 계산하지 못하게 막으려고
③가상 함수로 선언하면 실행 속도가 느려지기 때문
④직원 종류마다 계산 방법이 달라, 기반 클래스에 둘 만한 기본 구현이 없기 때문

정답 및 해설 보기

정답 ④

월급제·수수료제·기본급+수수료제는 계산식이 서로 다릅니다. 기반에 둘 근거가 없으니 = 0으로 두고, 각 파생 클래스가 자기 식을 제공하게 합니다.

Q8. 같은 Employee 계층에서 print()는 가상 함수이지만 순수 가상은 아닙니다. 그 이유로 가장 알맞은 것은?

①이름을 출력하는 공통 부분이 있어 기반에 기본 구현을 둘 수 있기 때문
②print는 다형적으로 호출되지 않기 때문
③순수 가상으로 만들면 컴파일 오류가 나기 때문
④파생 클래스가 print를 재정의하지 못하게 하려고

정답 및 해설 보기

정답 ①

이름·주민번호처럼 모든 직원에 공통인 출력이 있어 기반에 기본 구현을 두고, 파생 클래스는 필요하면 자기 몫을 덧붙입니다. 재정의는 선택이므로 virtual만 붙입니다.

Q9. SalariedEmployee::print()에서 Employee::print();를 먼저 호출하는 이유는?

①기반 클래스의 소멸자를 부르기 위해
②기반 클래스에 있는 공통 출력을 그대로 재사용하기 위해
③가상 함수 호출을 막기 위해
④파생 클래스의 print를 숨기기 위해

정답 및 해설 보기

정답 ②

이름 출력 같은 공통 부분을 기반에 맡기고 파생은 자기 몫만 덧붙입니다. 같은 코드를 복사하지 않으므로 공통 형식이 바뀌어도 한 곳만 고치면 됩니다(진단 3에서 이 줄을 빼면 이름이 사라집니다).

Q10. 다음 코드의 실행 결과로 옳은 것은?

class Employee {

public:

int main() {
    SalariedEmployee kim;
    Employee* p = &kim;
    Employee& r = kim;
    kim.print(); p->print(); r.print();

①Employee Employee Employee
②Salaried Salaried Employee
③Salaried Salaried Salaried
④컴파일 오류가 난다.

Q13. 스트림에 대한 설명으로 옳은 것은?

①스트림은 파일에만 쓰이는 개념이다.
②스트림은 바이트의 나열이며, 입력은 장치에서 주기억장치로 바이트가 흘러 들어오는 것이다.
③입력 스트림과 출력 스트림은 같은 객체다.

Q15. cerr와 clog에 대한 설명으로 옳은 것은?

①cerr는 버퍼를 쓰지 않아 출력이 곧바로 나타나고, clog는 버퍼가 차거나 flush될 때까지 붙잡아 둔다.
②cerr는 버퍼를 쓰고 clog는 쓰지 않는다.
③둘 다 표준 출력 장치에 연결되어 있다.
④둘 다 파일에만 쓸 수 있다.

정답 및 해설 보기

정답 ①

둘 다 표준 오류 장치에 연결되지만 cerr는 버퍼를 쓰지 않고, clog는 버퍼를 씁니다. 다만 둘 다 표준 오류에 붙어 있어서, 리다이렉션 없이는 두 스트림이 화면에서 구분되지 않습니다.

②again 다음 줄에 A

제공 코드

제공 코드 A — Employee 계층 (파일 employee_diag.cpp)

// 진단 제공 코드 A ─ 정상 동작하는 기준선 (12.5~12.6)
#include <iostream>
#include <string>
#include <vector>
using namespace std;

class Employee {
public:
    Employee(const string& name) : name_(name) {}
    virtual ~Employee() { cout << "[dtor] Employee(" << name_ << ")" << endl; }

    const string& getName() const { return name_; }

    virtual double earnings() const = 0;          // 순수 가상 ─ Employee는 답을 모른다
    virtual void print() const { cout << "name: " << name_ << ", "; }

private:
    string name_;
};

class SalariedEmployee : public Employee {
public:
    SalariedEmployee(const string& name, double salary)
        : Employee(name), salary_(salary) {}
    ~SalariedEmployee() { cout << "[dtor] Salaried(" << getName() << ")" << endl; }

    double earnings() const override { return salary_; }
    void print() const override { Employee::print(); cout << "salary: " << earnings() << endl; }

private:
    double salary_;
};

class CommissionEmployee : public Employee {
public:
    CommissionEmployee(const string& name, double rate, double sales)
        : Employee(name), rate_(rate), sales_(sales) {}
    ~CommissionEmployee() { cout << "[dtor] Commission(" << getName() << ")" << endl; }

    double earnings() const override { return rate_ * sales_; }
    void print() const override { Employee::print(); cout << "commission: " << earnings() << endl; }

private:
    double rate_, sales_;
};

int main() {

    staff.push_back(new CommissionEmployee("Lee", 0.25, 8000));

진단 문항

진단 6 — int ch를 char ch로 바꾼다 (설명형)

아래 코드는 cin.get()의 반환값을 char에 담았습니다. 실행해 보지 말고 왜 이렇게 쓰면 안 되는지 서술하십시오. 질문은 두 개입니다.

char ch;                                        // 원래 코드는 int ch;
while ((ch = cin.get()) != EOF)
    cout.put(ch);
  1. cin.get()은 무엇을 돌려주며, 파일 끝에서는 어떤 값이 오는가?
  2. char로 받으면 그 값이 왜 EOF와 구분되지 않는가?

모범 답안 cin.get()은 int를 돌려줍니다. 문자가 오면 그 문자의 코드값('a' → 97), 파일 끝이면 EOF(-1) 입니다. 그런데 1바이트가 가질 수 있는 값은 0~255이므로 255(0xFF)라는 바이트도 정상 입력으로 들어올 수 있습니다. char는 256가지 값만 담으므로 255와 -1(EOF)을 구분하지 못합니다. 이 환경(char가 signed)에서는 255를 담는 순간 -1이 되어 정상 문자를 파일 끝으로 착각하고, char가 unsigned인 환경에서는 반대로 EOF가 255가 되어 입력을 다 읽고도 반복이 끝나지 않습니다. 그래서 int로 받고, 출력할 때만 static_cast<char>로 좁힙니다.

이 문항은 실험 대신 추론으로 냅니다. 0xFF 바이트를 키보드로 넣을 수 없어 파일을 만들어야 하고(기존 안), 파일 입출력을 아직 배우지 않은 상태라 부적절합니다. 증상은 위 모범 답안에만 남깁니다.

진단 문항

진단 7 — cin.get()을 cin >> c로 바꾼다

제공 코드 B의 반복을 이렇게 바꿉니다.

char c;
while (cin >> c)                                // get() 대신 >> 로 받는다
    cout.put(c);

입력: a b 다음 줄에 c d (공백 3개 + 줄바꿈 1개)

  • 증상 원래 코드는 a b / c d가 공백과 줄바꿈까지 그대로 돌아온다. 바꾼 코드는 abcd 가 나온다(실측). 공백과 줄바꿈이 모두 사라진다.
  • 원인 >> 연산자는 공백 문자를 건너뛰고 다음 항목을 읽는다(13.4). get()은 공백을 포함한 모든 문자를 그대로 준다(13.4.1). 같은 입력이라도 어느 쪽으로 읽느냐에 따라 결과가 달라진다.
  • 수정 cin.get()으로 되돌린다.
  • 덧 화면에서 바로 확인되므로 리다이렉션이 필요 없다.

진단 문항

진단 8 — cout.put(static_cast<char>(ch))를 cout << ch로 바꾼다

  • 증상 abc⏎를 입력하면 abc가 아니라 97989910 이 출력된다(개행까지 숫자로 나온다).
  • 원인 ch가 int이므로 <<가 문자 대신 정수를 출력한다.
  • 수정 put(static_cast<char>(ch))로 되돌린다.

#pragma once
#include <iostream>
#include <string>

class Unit {
public:
    Unit(const std::string& name, int hp);
    ~Unit();

    int hp() const;

요구 사항

  1. Unit은 객체를 직접 만들 수 없는 클래스여야 한다. 이를 위해 위 Unit의 각 함수에 virtual, = 0을 붙일지, 소멸자를 어떻게 선언할지는 직접 결정한다. 파생 클래스에서 재정의하는 함수에는 override를 붙인다. 필요하면 멤버를 추가해도 된다. 결정한 이유는 설계 카드에 적는다
  2. 결정의 결과로 다음이 성립해야 한다
  • attack()과 type()은 유닛마다 다르게 동작한다
  • print(std::ostream&)의 공통 형식(종류·이름·체력)은 Unit이 출력하고, 파생은 자기 몫만 덧붙인다
  • 기반 포인터로 delete해도 파생 클래스의 소멸자까지 호출된다(소멸자에서 로그를 출력할지는 자유. 아래 예시 출력의 [dtor] 줄은 모범 답안이 로그를 넣은 경우다)
  1. 파생 클래스를 최소 두 개 만든다(예: Warrior는 공격력이 그대로 피해, Archer는 공격력 + 민첩/2)
  2. vector<Unit*>에 담아 기반 포인터만으로 print와 attack을 호출한다

전투 진행 부분은 예시로 제공합니다. 그대로 써도 되고, 바꾸고 싶으면 바꿔도 됩니다.

// main.cpp ─ 예시 전투 루프. 그대로 써도 되고, 바꾸고 싶으면 바꿔도 된다.
#include <iostream>
#include <vector>
#include "Unit.h"                               // 직접 만든 유닛 클래스 헤더

// 살아 있는 첫 유닛을 돌려준다. 없으면 nullptr
static Unit* firstAlive(std::vector<Unit*>& team) {
    for (Unit* u : team)
        if (u->alive()) return u;
    return nullptr;
}

// attackers의 살아 있는 유닛이 차례로 defenders의 살아 있는 첫 유닛을 공격한다
static void attackPhase(std::vector<Unit*>& attackers, std::vector<Unit*>& defenders,
                        const char* label, std::ostream& out) {
    for (Unit* a : attackers) {
        if (!a->alive()) continue;
        Unit* target = firstAlive(defenders);
        if (target == nullptr) return;

        int damage = a->attack();               // 가상 함수 ─ 유닛마다 다른 계산
        target->takeDamage(damage);
        out << label << " " << a->name() << " -> " << target->name()
            << " : " << damage << " damage, " << target->name()
            << " hp " << target->hp();
        if (!target->alive()) out << " (defeated)";
        out << '\n';
    }
}

int main() {
    std::vector<Unit*> heroes  { new Warrior("Conan", 100, 12), new Archer("Legolas", 80, 11, 6) };
    std::vector<Unit*> enemies { new Mage("Saruman", 70, 18, 20), new Warrior("Orc", 60, 9) };

    for (int round = 1; round <= 3; ++round) {  // 한 라운드 = 아군 전원 공격 → 적군 전원 공격
        std::cout << "--- round " << round << " ---\n";
        attackPhase(heroes, enemies, "hero", std::cout);
        attackPhase(enemies, heroes, "enemy", std::cout);
    }

    std::cout << "--- result ---\n";
    for (Unit* u : heroes)  { u->print(std::cout); std::cout << '\n'; }
    for (Unit* u : enemies) { u->print(std::cout); std::cout << '\n'; }

    for (Unit* u : heroes)  delete u;
    for (Unit* u : enemies) delete u;
}

요구 사항

  1. 파생을 하나 더 만든다(예: Mage — 마나가 있으면 두 배로 때리고 마나를 10 소모)
  2. 두 팀을 std::vector<Unit*>로 만들고 3라운드 동안 공격을 주고받는다. 위 예시 루프를 그대로 써도 된다
  3. 루프를 바꾸더라도 루프 안에서 type()이나 dynamic_cast로 분기하지 않는다 — attack() 하나만 부르고 나머지는 가상 함수가 알아서 한다
  4. 결과 출력은 print(std::cout)으로, 각 유닛의 종류·이름·남은 체력이 나오게

예시 출력은 모범 답안(위 예시 루프와 유닛) 기준이며, 유닛 규칙에 따라 숫자는 달라도 됩니다.

확인 포인트

  1. 확장 시험 — 네 번째 유닛 종류(예: Healer나 Thief)를 추가할 때 루프를 몇 줄 고쳤는가. 0줄이면 설계가 맞다. 새 클래스와 팀 구성 줄만 추가되고 루프는 그대로여야 한다

   A Legolas 80 11 6               ← 이름, 체력, 공격력, 민첩

위 형식은 모범 답안 기준이다. 유닛을 다르게 설계했다면 자기 유닛에 맞게 필드를 바꿔도 된다(첫 항목은 종류). 입력 끝은 Ctrl+Z(Visual Studio 콘솔). while (cin >> kind) 형태

  1. 체력이 0 이하인 줄은 등록하지 않고 std::cerr로 경고한 뒤 다음 줄로 넘어간다
  2. 알 수 없는 종류는 std::cerr로 알리고 읽기를 멈춘다
  3. 전투 후 printReport(heroes, std::cout)과 printReport(enemies, std::cout)로 결과를 출력

void printReport(const std::vector<Unit*>& team, std::ostream& out) {
    for (int i = 0; i < 44; ++i) out.put('-');       // 구분선은 put 으로 한 글자씩
    out << '\n';
    for (const Unit* u : team) {
        u->print(out);                               // 가상 함수가 파생 버전을 고른다
        out << '\n';
    }
}

확인 포인트

  1. 입력을 W Conan 100 12처럼 공백을 여러 개 넣어도 같은 결과인 이유 — >>가 공백을 건너뛰고 항목 단위로 읽는다(진단 7과 같은 성질)
  2. printReport(heroes, std::cout)을 std::cerr로 바꾸면 어디로 가는가 — 화면에 그대로 나오지만 표준 오류 스트림으로 나간다. ostream& 하나로 출력 대상을 바꿀 수 있다
  3. 경고가 전투 로그보다 먼저 보이는 이유 — 경고는 입력 중 cerr로, 전투 로그는 그 뒤 cout으로 나가기 때문
  4. while (cin >> kind)가 언제 끝나는가 — 입력이 끝나면 >>가 스트림을 실패 상태로 만들고 그 값이 조건식에서 거짓이 된다
