Q01

상속이 소프트웨어 재사용성을 높이는 까닭으로 가장 알맞은 것은?

기반 클래스의 코드를 파생 클래스마다 복사해 두므로, 한 클래스를 고쳐도 다른 클래스는 그대로 둘 수 있다
같은 기능이 기반 클래스 안에 하나의 사본으로만 존재해, 고칠 곳이 한 곳으로 줄어든다
파생 클래스가 기반 클래스의 private 멤버까지 직접 수정할 수 있기 때문이다
상속을 쓰면 같은 일을 하는 코드의 실행 속도가 항상 빨라지기 때문이다
복사·붙여넣기는 같은 코드의 사본이 시스템 곳곳에 퍼져, 한 곳을 고칠 때 나머지 사본도 모두 고쳐야 하는 유지보수의 악몽을 만듭니다. 상속은 그 기능이 기반 클래스 안에 하나의 사본으로만 존재하게 합니다. (p.38, p.52)

Q02

한 단계 위 클래스로부터 직접 상속받았을 때, 그 위 클래스를 가리키는 용어는?

간접 기반 클래스(indirect base class)
추상 기반 클래스(abstract base class)
직접 기반 클래스(direct base class)
가상 기반 클래스(virtual base class)
한 단계 위는 직접 기반 클래스, 두 단계 이상 위는 간접 기반 클래스입니다. 하나의 기반 클래스로부터만 상속하는 것은 단일 상속(single inheritance)이고, 여러 기반 클래스로부터 상속하는 다중 상속은 교재 24장에서 다룹니다. (p.4)

Q03

“기본급 직원은 커미션 직원이다”와 “자동차는 핸들을 가진다”의 관계를 옳게 짝지은 것은?

앞은 is-a(상속), 뒤는 has-a(컴포지션)
앞은 has-a(컴포지션), 뒤는 is-a(상속)
둘 다 is-a 관계다
둘 다 has-a 관계다
“모든 자동차는 탈것이지만, 모든 탈것이 자동차는 아니다”가 is-a의 핵심입니다. has-a는 객체가 다른 클래스의 객체를 하나 이상 멤버로 포함하는 관계입니다. (p.6)

Q04

다음 코드에서 Base의 public 멤버는 Derived 안에서 어떤 접근 범위가 되는가?

class Base { };
class Derived : Base { };
public
protected
Base와 같은 범위가 유지된다
private
class의 기본 상속은 private 상속입니다. public 상속을 하려면 : public Base처럼 지정자를 반드시 써야 합니다. 지정자를 빠뜨리면 기반의 public 멤버가 파생의 private가 되어 밖에서 쓸 수 없고, 파생 객체를 기반 참조에 담을 수도 없습니다(진단 3번). (p.5, p.12)

Q05

기반 클래스의 private 멤버에 대한 설명으로 옳은 것은?

상속되지 않으므로 파생 객체 안에는 존재하지 않는다
상속되지만 파생 클래스가 이름으로 접근할 수 없어, 기반 클래스가 제공하는 get/set을 통해야 한다
상속되고 파생 클래스에서 이름으로 자유롭게 접근할 수 있다
상속되지만 파생 클래스에서는 읽기만 가능하고 쓰기는 할 수 없다
교재 p.12는 “직접 접근 불가, 그러나 여전히 상속됨”으로 정리합니다. 파생 클래스가 private 데이터에 이름으로 접근하면 컴파일러가 오류를 냅니다. (p.12, p.46)

Q06

기반 클래스의 friend 함수는 파생 클래스에 상속되는가?

상속된다
public 상속일 때만 상속된다
상속되지 않는다
기반 클래스가 protected로 열어 두면 상속된다
friend는 “그 클래스의 friend”일 뿐이고, 상속 관계는 멤버에만 적용됩니다. (p.12)

Q07

protected 멤버에 접근할 수 있는 대상으로 옳지 않은 것은?

기반 클래스의 멤버 함수
기반 클래스의 friend 함수
파생 클래스의 멤버 함수
main 같은 외부 함수
public과 private 사이의 중간 보호 수준입니다. protected는 “파생 클래스까지” 열린 범위이고, main 같은 외부 함수는 여기에 들어가지 않습니다. (p.13, 실습 3)

Q08

파생 클래스에서 print()를 재정의했습니다. 여기서 기반 클래스의 print()를 부르는 코드로 옳은 것은?

CommissionEmployee::print();
print();
super.print();
base.print();
기반 클래스 이름과 이항 범위 지정 연산자 ::를 씁니다. 파생 클래스 안에서 이름만 쓴 print()는 자기 자신을 다시 부르는 무한 재귀가 됩니다. C++에는 super가 없습니다. (p.13)

Q09

생성자와 파생 클래스의 초기화에 대한 설명으로 옳은 것은?

생성자는 상속되므로 파생 클래스에서 다시 정의할 필요가 없다
생성자는 상속되지만 인수가 있는 생성자만 상속된다
생성자는 상속되지 않으며, 파생 생성자의 초기화 구문에서 기반 생성자를 부른다
생성자는 파생 생성자의 본문에서 부르는 것이 표준 방식이다
기반 생성자를 본문에서 부르면 이름 없는 임시 객체만 만들어지고, 그 전에 기반 부분을 만들 기본 생성자가 필요해 컴파일 오류가 납니다(진단 2번). 기반 생성자가 먼저, 그 다음 멤버가 초기화됩니다. (p.39, p.46)

Q10

파생 클래스의 헤더가 기반 클래스의 헤더를 include해야 하는 이유로 옳지 않은 것은?

컴파일러가 기반 클래스의 존재를 알아야 한다
파생 클래스가 기반 클래스의 private 멤버에 접근할 수 있어야 한다
상속된 데이터 멤버의 크기를 알아야 한다
상속된 클래스 멤버가 올바르게 쓰였는지 검사해야 한다
이유는 ① 존재 ② 상속된 데이터 멤버의 크기 ③ 상속된 멤버 사용의 검사입니다. private 멤버 접근은 include와 무관하게 언제나 막힙니다. 전방 선언만으로는 세 가지를 할 수 없어 컴파일 오류가 납니다. (p.47)

Q11

protected 데이터를 쓰는 방식의 장점과 단점을 옳게 설명한 것은?

장점 — 유효성 검사가 강제된다. 단점 — set/get 호출 때문에 느려진다
장점 — 상속이 필요 없어진다. 단점 — 컴파일 시간이 길어진다
장점도 단점도 없다. 관례일 뿐이다
장점 — set/get 호출 없이 값을 다뤄 오버헤드가 줄어든다. 단점 — 검증을 거치지 않은 값이 저장되고, 기반 구현에 의존하게 된다
실습 3에서 gross sales: -9000.00, commission rate: 2.50이 아무 저항 없이 저장되는 것을 확인합니다. 구현이 바뀌면 파생 클래스도 고쳐야 하는 취약한(brittle) 소프트웨어가 됩니다. (p.53)

Q12

11.3.5가 결론으로 제시한 “최선의 소프트웨어 공학 실천법” 세 가지로 옳은 것은?

데이터 멤버를 private로 선언하고, public get/set을 제공하며, set에서 검증된 값만 저장한다
데이터 멤버를 protected로 선언하고, 파생 클래스가 직접 접근하게 한다
데이터 멤버를 public으로 선언하고, 규칙을 주석으로 문서화한다
데이터 멤버는 friend 함수로만 다루게 한다
protected로 열었다가 다시 private로 돌아오는 것이 이 절의 결론입니다. (p.54, 그림 11.15)

class BasePlusCommissionEmployee : public CommissionEmployee {

double BasePlusSalariedEmployee::getBaseSalary() const { return baseSalary; }

double BasePlusSalariedEmployee::earnings() const { return baseSalary + base.earnings(); }

         << ' ' << base.getLastName()
         << "\nsocial security number: " << base.getSocialSecurityNumber()
         << "\ngross sales: " << base.getGrossSales()
         << "\ncommission rate: " << base.getCommissionRate()
         << "\nbase salary: " << baseSalary;
}

과제 5 · [난이도 상] 3단계 상속 계층 완성하기훈련: 구현

CommissionEmployee → BasePlusCommissionEmployee(과제 2 결과물) → SeniorBasePlusCommissionEmployee로 계층을 한 단계 더 내려갑니다. 각 단계가 직계 기반의 함수를 재사용해 연쇄하는 구조를 만듭니다.

  • class SeniorBasePlusCommissionEmployee : public BasePlusCommissionEmployee
  • 새 데이터 두 개를 private로 — double incentive(성과급), int yearsOfService(근속 연수). 각각 음수를 거부하는 setter를 만든다("Incentive must be >= 0.0", "Years of service must be >= 0").
  • 생성자는 직계 기반 클래스 생성자만 호출한다. CommissionEmployee(...)를 직접 부르지 않는다.
  • earnings() = BasePlusCommissionEmployee::earnings() + incentive
  • print()는 "senior "를 먼저 찍고 BasePlusCommissionEmployee::print()를 부른 뒤 incentive와 years를 찍는다.
  • main ① Dana Park, 555-55-5555, 12000, .06, 900, 성과급 250, 근속 7 ② 상속받은 getter로 이름·총매출·기본급 확인 ③ CommissionEmployee& ref = s1; 후 ref.earnings() ④ 잘못된 값 두 번(성과급 -50, 근속 -1)
  • 제출물에 두 문장 — ③에서 왜 1870.00이 아니라 720.00이 나왔는가(힌트: 변수의 정적 형식이 무엇을 결정하는가)

리뷰 체크리스트 — 4항목

  • 파생 클래스가 기반의 private 멤버에 직접 접근하지 않는가
  • 기반 생성자를 초기화 리스트에서 부르는가 (본문 대입이 아니라)
  • 재정의한 함수가 기반 함수를 이름만으로 불러 무한 재귀하지 않는가
  • public 상속인가 (class 뒤에 아무것도 안 썼다면 private 상속)
